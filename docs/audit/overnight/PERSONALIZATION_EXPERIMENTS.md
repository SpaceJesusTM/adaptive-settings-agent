# Personalization experiments

GamePlan already records settings and provenance. Settings seed values, edited values, confirmed priority records, current objectives and hypotheses derived from behavior have different meanings. The overnight experiment uses the original event history as the evidence source.

| Evidence | Use in the implementation |
| --- | --- |
| Explicit, grounded memory instruction or accepted preference chip | Confirmed preference or personal fact in System Understanding. Preserve scope and the existing removal or Undo path. |
| Current objective and explicitly protected controls | Session-scoped context for chat, Discover and Apply. A new goal can override ranking for the session while the confirmed preference remains inspectable. |
| Independent manual edits | Show the actual choices immediately in What I've Noticed. Use them as tentative cross-session evidence after two different controls in at least two sessions support the same dimension in the same game. |
| Preset, proposal acceptance or edited proposal later applied | Show the committed provenance. These decisions supply no positive evidence for the longitudinal dimension. |
| Undo or later overriding value | Invalidate superseded evidence. A still-current manual move away from a dimension's preferred set vetoes that tentative dimension. |
| Dismissal, navigation or explanation request | Use a dismissal for existing suppression and a recent linked setting as exposure when ranking. These actions supply no durable preference or evidence of understanding. |
| Other game or hardware | Keep hypotheses game-scoped. Use documented analogues and actual source values for cross-game inspection. Use simulated hardware as availability context. |

[The observation code](../../../backend/app/domain/observations.py) matches a manual event's revision to the current value revision and checks confirmed-priority dimensions before emitting a tentative pattern. A restored edit, an AI-applied value and an unrelated preset supply different evidence even when their final values equal a deliberate manual choice. A soft pattern influences an optional Discover inspection. The default planner assigns it no objective weight. A single manual edit names the event and its plausible purpose in the UI. It is excluded from the prompt's cross-session pattern and from utility ranking.

## Controlled cases

- **Same final state, different history.** In CS2, initialize Boost Player Contrast and Dynamic Shadows to Disabled and Sun Only. In one history turn each control on manually in a different session. In the control history apply the same two values together from a synthetic draft. The candidate reports tentative visibility evidence only for the independent manual history. Both leave confirmed memory empty. The first audit misses the across-session pattern in this fixture. When utility Discover is enabled, the manual history also adds a Global Shadow Quality inspection that compares the encountered Dynamic Shadows control. With the same final values and an accepted draft, Discover shows only its two onboarding checks. The default policy shows those two checks in both histories.
- **Cross-game starts with ordinary use.** In baseline VALORANT set sensitivity, Push to Talk and Ping from canonical controls. Open adaptive CS2 and inspect source-grounded onboarding before asking chat to transfer anything. The default policy passes this workflow using the existing observations. The utility variant also passes the frozen five checks. Only the sensitivity comparison offers a numerical starting point, with the equal-DPI condition.
- **Temporary versus durable.** A request to remember a normally preferred goal and a later one-session objective produce distinct records. The [browser goal-shift journey](../../../frontend/e2e/journeys.spec.ts) verifies the earlier draft becomes outdated. The [first audit's matched goal controls](../EVALUATION_RESULTS.md) establish preference coexistence and correction.
- **Insufficient signal.** A confirmed Voice Activation habit can be preserved as a game-scoped fact. A bare quoted preference example, an uncertain reference, a temporary exact volume value and the accepted-plan control create no extra confirmed preferences.

The two-session threshold is a conservative heuristic. A saved simulator session ID survives a page reload and normal app reopening. The benchmark uses the existing AI-only research reset to create separate IDs while preserving actual manual history. This proves the policy over recorded session boundaries. Inferring naturally separate play sessions remains future work. It cannot distinguish a habit from two experiments or two independent context changes. The project has yet to calibrate evidence decay or measure the burden of the interface with participants. A report that an edit “can support” visibility leaves the player's motivation open. See [the ReLay and Alves et al. studies](../LITERATURE_REVIEW.md) for the motivation to expose inspectable interaction history.

The default interaction still starts with ordinary use. System Understanding remains the recovery and inspection surface. Show the current reason near a recommendation or discovery, using the specific setting and its source. Use the existing correction path when an explicit preference is wrong. An evidence-specific “That was an experiment” control is a research option if pilot participants repeatedly try to correct an observation.
