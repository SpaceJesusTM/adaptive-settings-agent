## MAESTRO Movie

**Preference extraction and lifetime.** The exact implemented extraction prompt takes the current workflow stage, a compact visible UI state, recent dialogue, and the existing list. It distinguishes choosing from a shortlist after a prompt from volunteering a criterion. It asks the model to split hard acceptance criteria and soft tie-breakers, keep qualifiers in the description, assign relevant stages, and preserve unaffected entries. Each record has `id`, `description`, `strength`, and `relevantStages`. The model returns `hasUpdate` and a full proposed list. The application derives IDs from normalized descriptions and replaces the list on an update. `AgentMemory.reset()` clears it at session reset. The schema has no separate fields for evidentiary provenance, scope across products, or expiry. Copying full-list replacement would expose GamePlan's unrelated durable preferences to accidental removal. The current normalizer also treats unknown strength values as hard, despite the prompt giving ambiguous statements soft strength. [Extraction prompt and parser](https://github.com/wooogler/maestro-movie/blob/b8d132c17c94e5e59ab859bf2dc7b0291c1b31fa/apps/tuning-agent/src/llm/llmExtractor.ts#L70-L95), [extraction request and JSON schema](https://github.com/wooogler/maestro-movie/blob/b8d132c17c94e5e59ab859bf2dc7b0291c1b31fa/apps/tuning-agent/src/llm/llmExtractor.ts#L588-L665), [runtime types](https://github.com/wooogler/maestro-movie/blob/b8d132c17c94e5e59ab859bf2dc7b0291c1b31fa/apps/tuning-agent/src/types.ts#L19-L91), [preference IDs](https://github.com/wooogler/maestro-movie/blob/b8d132c17c94e5e59ab859bf2dc7b0291c1b31fa/apps/tuning-agent/src/core/cpMemory.ts#L154-L157), [session state](https://github.com/wooogler/maestro-movie/blob/b8d132c17c94e5e59ab859bf2dc7b0291c1b31fa/apps/tuning-agent/src/core/memory.ts#L80-L104).

**Propagation and conflict.** Both GUI adaptation and workflow navigation receive the same preference records through the planner. The planner prompt applies hard requirements first, keeps the feasible set available while using soft preferences as tie-breakers, and offers backtracking to the nearest earlier stage with viable alternatives when a hard constraint blocks progress. The runtime stores blocked branches with the stage and relevant selections, and records filters and highlights with the preference IDs and strength that justified them. When a preference changes, `setPreferences` drops dead ends that lost qualifying hard support and drops filter/highlight evidence with invalid bindings. Alternative counts use recorded stage state. The policy therefore combines model judgments about conflicts with deterministic bookkeeping, tool gating, and visibility checks. [Planner prompt and adaptation rules](https://github.com/wooogler/maestro-movie/blob/b8d132c17c94e5e59ab859bf2dc7b0291c1b31fa/apps/tuning-agent/src/llm/llmPlanner.ts#L271-L380), [dynamic prompt assembly](https://github.com/wooogler/maestro-movie/blob/b8d132c17c94e5e59ab859bf2dc7b0291c1b31fa/apps/tuning-agent/src/llm/llmPlanner.ts#L399-L451), [alternative calculation and planning input](https://github.com/wooogler/maestro-movie/blob/b8d132c17c94e5e59ab859bf2dc7b0291c1b31fa/apps/tuning-agent/src/core/planner.ts#L772-L889), [evidence invalidation](https://github.com/wooogler/maestro-movie/blob/b8d132c17c94e5e59ab859bf2dc7b0291c1b31fa/apps/tuning-agent/src/core/memory.ts#L355-L408).

**Adaptation and feedback.** The planner can augment visible item text, filter, sort, highlight, or clear a modification. Its prompt first surfaces decision attributes needed to interpret the suggestion and uses tool availability and the current visible set to constrain selections. The host acknowledges tool execution and separately emits authoritative state changes from direct manipulation, navigation, and tool use. The runtime resolves committed selections on stage transitions and re-syncs after errors or selected tool outcomes. Inspectable study assets include scenario definitions and a review surface. The paper evaluated the bundled interface and workflow on movie booking with fixed preference criteria. It describes extraction refinement in pilots and leaves isolated extraction accuracy for future work. The repository identifies GPT-5.4 as the study model. The study provides design evidence for using one preference interpretation across linked decisions. GamePlan needs its own evidence on flexible goals and small-model latency. [Tool schema](https://github.com/wooogler/maestro-movie/blob/b8d132c17c94e5e59ab859bf2dc7b0291c1b31fa/apps/frontend/src/agent/tools.ts#L27-L159), [host relay state and acknowledgments](https://github.com/wooogler/maestro-movie/blob/b8d132c17c94e5e59ab859bf2dc7b0291c1b31fa/docs/external-agent-protocol.md#L191-L239), [runtime workflow synchronization](https://github.com/wooogler/maestro-movie/blob/b8d132c17c94e5e59ab859bf2dc7b0291c1b31fa/apps/tuning-agent/src/index.ts#L1584-L1630), [scenario definitions](https://github.com/wooogler/maestro-movie/tree/b8d132c17c94e5e59ab859bf2dc7b0291c1b31fa/docs/scenarios), [model configuration](https://github.com/wooogler/maestro-movie/blob/b8d132c17c94e5e59ab859bf2dc7b0291c1b31fa/README.md#L80-L95), [paper implementation, evaluation, and limitations](https://arxiv.org/html/2604.06134v2).

In the 33-person within-subject study, the bundled system reduced final hard-preference violations (regression coefficient −0.80, p = .047) and intermediate unpreferred selections (−0.56, p = .008). The authors reported no statistically significant difference in binary task success or completion time. GamePlan should score violations and recoverable intermediate mistakes separately from whole-task completion. The paper's appendix also publishes the study prompts, which complement the runtime templates above. [Paper results §5.1.1 and study prompts §A.6](https://arxiv.org/html/2604.06134v2).

**Transfer to GamePlan.** Keep canonical menus stable. Let a criterion's stable ID, scope, and provenance drive both chat and any optional discovery card. On correction, recompute dependent assistance from current evidence. Treat unambiguous hard exclusions as deterministic eligibility constraints and temporary goals as context for ranking. Keep observed edits, procedural acceptance, and declared preferences distinct. Simulate a prompted choice followed by a spontaneous declaration, then withdraw it. Check durable memory writes, both surfaces' outputs, unrelated preference retention, exclusions, and revision latency (DG1, DG3, DG4).

## NVIDIA Project G-Assist

**Public capabilities.** NVIDIA documents knowledge queries, hardware-aware graphics optimization and reversal, telemetry and diagnostics while a game runs, and separate V-Sync state queries and mutations. These commands act on supported real systems through the NVIDIA overlay. The public repository gives the integration boundary: built-in commands go to core functions, and plugin commands go through a separate JSON-RPC plugin engine. The Python binding registers a client and sends requests. The manifest declares tool names, use cases, intent tags, argument properties, and required fields. The SDK resolves a handler by function name, accepts structured context and system information, and emits result and error responses. The sample includes a basic command, streaming, and interactive follow-up. The repository exposes these contracts and user-facing examples. Core prompts, built-in ranking, and optimization internals were unavailable in the public source. [NVIDIA supported functions and product description](https://www.nvidia.com/en-us/software/nvidia-app/g-assist/), [public architecture and manifest contract](https://github.com/NVIDIA/G-Assist/blob/2f8b3b623b7cafe8e6e65ba76d0a544f1cb32add/README.md#L140-L223), [binding](https://github.com/NVIDIA/G-Assist/blob/2f8b3b623b7cafe8e6e65ba76d0a544f1cb32add/api/bindings/python/rise/rise.py#L214-L258), [example manifest](https://github.com/NVIDIA/G-Assist/blob/2f8b3b623b7cafe8e6e65ba76d0a544f1cb32add/plugins/examples/hello-world/manifest.json), [SDK dispatch](https://github.com/NVIDIA/G-Assist/blob/2f8b3b623b7cafe8e6e65ba76d0a544f1cb32add/plugins/sdk/python/gassist_sdk/plugin.py#L314-L354).

**Transfer to GamePlan.** The relevant precedent is a small model interpreting a bounded domain contract. GamePlan already has read-only catalogue, current state and history tools in `backend/app/agent/tools.py` and an explicit proposal boundary in `backend/app/domain/proposals.py`. Preserve that separation and give the model explicit applicability and unsupported outcomes from structured state. Compare explanation-only, specific configuration, and broad guidance turns on validated action and tool-call accuracy. G-Assist's telemetry and live optimization apply to its supported hardware and do not establish GamePlan's effects (DG2, DG3).

## LangMem

**Lifecycle and tools.** LangMem offers two paths: synchronous in-conversation manage/search tools against a LangGraph `BaseStore`, and asynchronous extraction or consolidation triggered outside the response path. The manage/search tools resolve the same templated namespace, from which source code dispatches bounded reads and ID-addressed create/update/delete operations. Separate extraction accepts custom schemas, existing memory IDs, configurable insert/update/delete permissions, and a bounded number of steps. Deletes default to disabled in `MemoryManager`. The store manager retrieves candidates and applies explicit puts and deletes. The published default memory instructions and request assembler define the exact template, with callers able to supply their own rules. [Hot-path tools and namespace resolution](https://github.com/langchain-ai/langmem/blob/4beb9c36a40953f09357e5b2dd62ecc726f22d13/src/langmem/knowledge/tools.py#L263-L353), [memory manager and default instructions](https://github.com/langchain-ai/langmem/blob/4beb9c36a40953f09357e5b2dd62ecc726f22d13/src/langmem/knowledge/extraction.py#L185-L276), [request construction](https://github.com/langchain-ai/langmem/blob/4beb9c36a40953f09357e5b2dd62ecc726f22d13/src/langmem/knowledge/extraction.py#L457-L478), [background example](https://github.com/langchain-ai/langmem/blob/4beb9c36a40953f09357e5b2dd62ecc726f22d13/docs/docs/background_quickstart.md).

**Transfer to GamePlan.** Deterministic namespace matching corresponds to its existing global and game-specific profile scope. Stable-ID corrections and a validator-owned write policy can stay in SQLite. Keep conversational interpretation off every response when it adds no useful detail. Before considering a new layer, compare structured retrieval with transcript-only and structured-plus-transcript variations on relevant-memory recall, false writes, latency, and supersession correctness. Generic memory management supplies operations and extraction machinery. GamePlan still needs its own semantics for one-night goals, accepted suggestions, and strong setting protections (DG3, DG4).

## Mem0

**Current OSS lifecycle.** At the inspected revision, `Memory.add` supports explicit storage through `infer=False` and inferred storage through an additive extraction path. The inferred path gathers recent scoped messages and nearest scoped memories, maps existing UUIDs to short local references, calls the additive extraction prompt, batches new embeddings, and deduplicates by hash. Search supports scoped metadata filters and optional reranking. Separate ID-addressed update/delete operations and a SQLite history journal retain old/new text and event metadata. The default update prompt is present in source as a distinct template. The inspected current add path uses the additive template, so the older template alone would misdescribe what runs. [Scoped add and extraction](https://github.com/mem0ai/mem0/blob/cae3d8cda89437863e047a311688d7f44cceef60/mem0/memory/main.py#L760-L1050), [public additive template](https://github.com/mem0ai/mem0/blob/cae3d8cda89437863e047a311688d7f44cceef60/mem0/configs/prompts.py#L468-L535), [update, delete, and history](https://github.com/mem0ai/mem0/blob/cae3d8cda89437863e047a311688d7f44cceef60/mem0/memory/main.py#L1829-L1973), [SQLite journal](https://github.com/mem0ai/mem0/blob/cae3d8cda89437863e047a311688d7f44cceef60/mem0/memory/storage.py#L150-L162), [lifecycle tests](https://github.com/mem0ai/mem0/blob/cae3d8cda89437863e047a311688d7f44cceef60/tests/test_memory.py).

**Transfer to GamePlan.** A memory can have an inspectable revision history and support correction by identity. GamePlan's setting and category keys can deliver stronger semantic deduplication for this catalogue than text hashes. Treat durable player declarations as model suggestions subject to a narrow policy, and commit accepted corrections plus provenance in the same SQLite transaction. The Mem0 design adds embedding retrieval and permissive natural-language memory to support larger, less structured collections. Those costs need a demonstrated recall problem on GamePlan's two catalogues before integration (DG4).

## PrefEval

**Protocol and artifacts.** Zhao et al. evaluate explicit, choice-based implicit, and persona-driven implicit preferences using 3,000 preference/query pairs across 20 topics. A late probe follows irrelevant intervening turns. Generation uses separate checks for acknowledgment, violation, hallucination, and helpfulness. Classification is another task with a curated answer. The method comparisons include a short reminder, few-shot reasoning, retrieval of history, and a multistep self-critique. Source includes the corpus loaders, prompt construction, judging templates and runners. In long contexts the experiments show weaker adherence, including the case where a preference is correctly repeated yet violated in the actual answer. The dynamic experiment probes a later conflicting statement and reports model-dependent results. It does not identify the correct precedence for a temporarily scoped override. The judges assess text and limited annotated examples, so the benchmark does not establish effects on application state or human decisions. [Paper sections 2–3 and appendices A.4, A.11 and A.16](https://arxiv.org/html/2502.09597v1), [generation runner](https://github.com/amazon-science/PrefEval/blob/50795054b5ff5f418d2b768a331d71e480f93331/generation_task/benchmark_generation.py), [classification runner](https://github.com/amazon-science/PrefEval/blob/50795054b5ff5f418d2b768a331d71e480f93331/classification_task/benchmark_classification.py), [explicit templates](https://github.com/amazon-science/PrefEval/blob/50795054b5ff5f418d2b768a331d71e480f93331/utils/explicit_utils.py), [implicit templates](https://github.com/amazon-science/PrefEval/blob/50795054b5ff5f418d2b768a331d71e480f93331/utils/implicit_utils.py), [judge templates](https://github.com/amazon-science/PrefEval/tree/50795054b5ff5f418d2b768a331d71e480f93331/error_type).

**Transfer to GamePlan.** Build new setting scenarios that vary evidence form, chat distance, game scope, corrections, and actual manual interactions. Pair each with a late action probe. Score recall, valid action, preference alignment and unnecessary personalization as separate outcomes. A reply that remembers a resolution exclusion and stages resolution still fails. A choice from a suggested shortlist can inform immediate context while leaving durable memory empty. Separate scorer rubrics from prompts and read structured application state first (DG3, DG4).

## TinyAgent

**Small-model tool selection.** The public implementation classifies the needed subset of 16 desktop tools, intersects it with available tools, retrieves examples using only that subset, then rebuilds the planning prompt. The paper's small-model planners were fine-tuned on task-specific synthetic data. Its evaluation uses matching tools and dependency structure against a reference plan. Tool selection must preserve dependencies with weak lexical matches. A naive retrieval baseline cut prompt size and worsened success in its benchmark. The reported improvements depend on its own trained selector and planner. Exact public planner text and composition are available. No models or weights were needed for this inspection. [Paper sections 3–4 and Table 1](https://aclanthology.org/2024.emnlp-demo.9.pdf), [classifier and retrieval implementation](https://github.com/SqueezeAILab/TinyAgent/blob/cc45c0e842f5d163c3df1c8f41d60e90e005867d/src/tiny_agent/tool_rag/classifier_tool_rag.py#L19-L113), [per-request prompt assembly](https://github.com/SqueezeAILab/TinyAgent/blob/cc45c0e842f5d163c3df1c8f41d60e90e005867d/src/tiny_agent/tiny_agent.py#L118-L152), [prompt source](https://github.com/SqueezeAILab/TinyAgent/blob/cc45c0e842f5d163c3df1c8f41d60e90e005867d/src/tiny_agent/prompts.py).

**Transfer to GamePlan.** For explicit tasks, pass a compact catalogue slice that includes the requested setting, known dependencies and contextual constraints. Retain broad catalogue coverage for broad objectives and allow expansion when a narrow search yields weak evidence. Measure target and dependency recall, follow-up correctness, prompt tokens, model calls, and p50/p95 where samples support them. A compact context is only a win if it preserves broad pilot-task coverage (DG1–DG3).

## Experiments justified by this review

| Hypothesis | Smallest informative comparison | Failure to watch |
| --- | --- | --- |
| Shared effective criteria reduce contradictory assistance | Run identical correction and temporary-goal sequences against baseline and the candidate. Compare Discover and chat after each state transition. | A card survives after its supporting criterion expires, or one surface overrides an active constraint. |
| Evidence-sensitive writes reduce false personalization | Contrast an accepted AI proposal, manual change, volunteered scope-specific preference, and explicit correction. Probe in both games after unrelated turns. | A one-off or prompted choice becomes a durable global preference, or an unrelated preference disappears on correction. |
| Bounded, typed grounding helps the local model | Compare equivalent narrow and broad tasks on the same local model, preserving catalogue IDs and relevant dependencies. | Faster output loses a required setting, changes a locked value, overstates performance, or replaces useful assistance with fallback. |
| Scoring recall separately from behavior reveals alignment failures | Score acknowledged objective, remembered scope, eligible surfaced actions, staged state, and committed settings independently. | Correct explanation masks an invalid or contradictory proposal. |

These patterns can be implemented independently of the external libraries. This review incorporates their documented mechanisms and links to their prompts and code. It does not incorporate third-party source, prompt templates, or benchmark records.
